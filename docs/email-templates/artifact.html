Instalar — 4 pasos, en el dashboard

  1. Abre las plantillas de Auth

    Authentication → Emails → Templates ↗

  2. Pega el HTML

    Por cada pestaña (Confirm signup / Magic Link / Reset Password), borra el cuadro "Message Body" y pega el .html correspondiente. Guarda.

  3. Pon el asunto

    Confirm signup
    Confirma tu cuenta en Ketzal OS
    Magic Link
    Tu enlace para entrar a Ketzal OS
    Reset Password
    Recupera tu contraseña de Ketzal OS

  4. Prueba con un correo real

    Pide un magic link o una recuperación real y confirma que llega con el diseño nuevo. Efecto inmediato al guardar — sin deploy, sin migración.

Dominio propio para el remitente — pendiente, sin dominio aún

Hoy el correo sale de la dirección genérica de Supabase. El HTML ya trae la marca Ketzal, pero el remitente no. Para que salga de algo como no-responder@ketzal.mx:

  1. Comprar el dominio

    Namecheap o GoDaddy, ~$150–300 MXN/año. No hace falta que la app viva ahí — solo se usa para enviar correo.

  2. Cuenta en Resend

    Recomendado: encaja con Vercel/Next.js, tier gratis generoso, guía oficial con Supabase. Alternativas: SendGrid, Postmark, AWS SES.

  3. Verificar el dominio

    Agrega los registros DNS que dé Resend (SPF, DKIM, de preferencia DMARC) en el panel del registrador. Sin esto el correo cae a spam o se rechaza.

  4. Conectar como SMTP custom en Supabase

    Authentication → Emails → SMTP Settings → activa "Enable Custom SMTP" con host/puerto/usuario/API key de Resend y el remitente final.

  5. Probar de nuevo

    Un correo real, remitente correcto, que no caiga a spam.

Cuando haya dominio, las plantillas de arriba no cambian — solo cambia por dónde sale el correo.
